# 行测题库 · 决战行测 5000 题

粉笔《决战行测 5000 题》（2025 年 9 月版）的本地题库学习系统，目前收录两套：

| 科目 | 题目册 | 答案册 | 题号前缀 |
| --- | --- | --- | --- |
| 判断推理 | 392 + 510 页扫描 PDF（全两册） | 同左 | 无（`c1-0001`，兼容历史学习记录） |
| 数量关系 | 256 + 368 页扫描 PDF（全两册） | 同左 | `sl-`（`sl-c1-0001`） |
| 资料分析 | 312 + 504 页扫描 PDF（全两册） | 同左 | `zl-`（`zl-c1-0001`，资料为 `zl-m0001`） |
| 言语理解 | 360 + 412 页扫描 PDF（全两册） | 同左 | `yy-`（`yy-c1-0001`） |

各模块**版式不同**，所以不是一个题库加个筛选字段，而是各自的解析器：判断推理/数量关系/言语理解
是「一题一干四选项」（题号在每个教学块内从 1 重启），资料分析是「**一段资料带一组小题**」
（题号在同一作业题内跨资料连续，第二组从 6 开始而不是从 1 重来）。

两套都是**纯扫描 PDF（无文字层）**，本项目用 OCR 管线把它们变成结构化题库，
并在 Next.js 里提供刷题、错题本、背诵、统计分析与原书对照的完整学习闭环。
题库在前端按「科目」切换；学习记录（SQLite）按全局唯一题目 ID 索引，两套共用一份。

## 技术选型

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 脚手架 | `create-next-app`（TypeScript + App Router + src/ + Tailwind CSS v4 + ESLint） | 官方脚手架一次到位，保留 `@/*` 别名与 Turbopack 配置 |
| 框架 | Next.js 16 App Router + React 19 | 服务端组件直接读 SQLite/JSON，无需单独后端；客户端组件只承担交互（刷题引擎、图表） |
| 样式 | Tailwind v4 + 少量 CSS 变量 | 明暗模式靠 `prefers-color-scheme` 的 token 切换；中文题干需要自定义 `.stem` 排版（1.95 行距、`pre-wrap`） |
| 题库数据 | 静态 JSON（`data/banks/<科目>/questions.json`） | 题库是**只读构建产物**，由 Python 管线生成；用文件而非数据库表，重建即覆盖，不污染学习记录 |
| 学习记录 | SQLite（`better-sqlite3`，`data/app.db`） | 单机多表事务（答题流水 → 错题本 → 间隔重复）用 SQL 聚合最省事；同步 API 简单、零运维 |
| 状态 | Zustand（刷题会话）| 会话有跨组件的队列/计时/作答状态，选择器订阅可避免整树重渲染 |
| 图表 | Recharts + 手写 SVG 日历热力图 | 折线/柱/雷达用 Recharts；热力图用 SVG 网格更可控 |
| OCR | PyMuPDF + RapidOCR(ONNX) + OpenCV | 见下 |

## 图形题的图怎么来：不做截图

扫描页每页是一张原生位图，所以**不需要屏幕截图**（截图会二次损失分辨率、
还要人工对齐题号）。管线是：

1. `pipeline/ocr_pages.py`：PyMuPDF 以 200 dpi 渲染整页 → RapidOCR 得到带坐标的文本块，
   每页缓存成 `data/ocr/<tag>/pNNN.json`（可断点续跑）。tag 由 `pipeline/books.py` 按册分配
   （判断：`up`/`dn`；数量：`sl-up`/`sl-dn`）。
2. `pipeline/parse_bank.py`：重建视觉行、识别章节/考点/子块结构、切题、并给每题算出
   **图形区**（题干最后一行以下、文字选项以上的区域）。
3. `pipeline/crop_images.py`：按图形区从 PDF **原始分辨率**做 clip 渲染（300 dpi），
   再用 OpenCV 二值化 + 行列投影裁到墨迹外接框。产出三类资产（所有科目共用，ID 不冲突）：
   - `public/assets/figures/<id>.png` 题干图 + 选项图（含印刷的 A/B/C/D）
   - `public/assets/crops/<id>.png` 整题原书裁剪，用于核对 OCR 与"这题原来看长什么样"
   - `public/assets/pages/<tag>-<NNN>.jpg` 整页缩略，供原书页面浏览器叠加题号框

只有像素里确实有墨迹时才判定为图形题，因此 `kind` / `hasImage` 是**经过像素验证**的，
而不是靠版式猜测。

## 问题和答案怎么对上（最重要的不变量）

- **题号会在每个教学块内从 1 重启**（考点 N、（一）夯实基础、综合练习二…），所以题号不是主键。
  两册条目顺序完全一致，因此下册按**顺序对齐**上册，并在题号上重新同步。
- **配对是审计出来的，不是默认可信的**：
  - 每条 `N.【答案】X` 锚点会与解析末尾的「故正确答案为X」交叉校验，不一致即打
    `answer-mismatch` 标记并写进 `issues.json`；
  - 答案字母必须存在于该题选项列表，否则打 `answer-not-in-options`；
  - 每章的题目数 / 答案数、编号断档、多余答案都记录在 `report.json` / `issues.json`；
  - `pipeline/audit_pairs.py --bank <科目>` 会把**全部带标记题 + 随机抽样**渲染成
    「上册题目裁剪 + 下册答案裁剪」拼图（`pipeline/_audit/`），供人工快速核对。
- **奇数页页眉本身就是"第 X 章 …"**，它是章号最可靠的来源，但不能像正文标题那样重置题号序列。
- **`考点介绍` 里的编号条目不是题**（`1.曲直性：根据…`）。判据：真题锚点必带 `（2024 山东 65）`
  来源标记，或紧跟在已确认题块后连续编号。`pipeline/test_parse.py` 把这些决定锁成回归测试。
- 数量关系存在 **A–H 八个选项**的江苏真题，管线与前端全部按 A–H 处理（快捷键 1–8）。
- **资料分析另有一条逐题证据**：粉笔的解析常以「根据题干“2023年…约是2020年…多少倍”」开头，
  引用的正是**这一道**小题的措辞。资料里的数字被同组五题共享，证明不了归属，这句引用可以。
  因此对齐时把「有决定性的题干引用」看得比印出来的题号更重（题号会被 OCR 读错），
  引用能唯一指认本题时允许跨题号配对；反之若引用明显指向别题，宁可留 `no-answer` 也不配对。
- 数字必须**整段相等**才算证据：`2012` 不能为 `12` 作证，`1一2月`（OCR 把范围破折号读成
  汉字「一」）可以为 `12月` 作证。引用里的高频词（同比增长…）按章内词频剔除，否则任何
  一道增长题都能“匹配”任何一条解析。

## 全量自证：每一道题都有结论

`python pipeline/verify_bank.py` 逐题跑一组**与配对逻辑无关**的断言，输出
`data/banks/<科目>/verification.json`（每题一条判决），并在 `/verification`（数据校验）页面呈现：

| 断言 | 检验方式 |
| --- | --- |
| 配对是否张冠李戴 | 解析自身的「根据题干“…”」引用与本题题干比对，并与**全库**其他题干竞争：只有别题明显更贴合才判为错配 |
| 解析是否讲本题的事 | 本题独有的数据值 / 去掉章内套话后的二元词与解析取交集 |
| 答案字母对不对 | 重新读该题所在下册页的 `N.【答案】X`，与入库答案逐字符比对；解析末尾「故正确答案为X」再交叉核对 |
| 选项完整性 | 答案字母必须在该题选项里 |
| 答案页顺序 | 同章内答案页码不得回退 |
| 答案侧清点 | 下册实际印刷的锚点数 vs 已被题目认领数（差额=未配上的答案） |

证据分级：`quoted`（逐题引用命中，最强）> `strong` > `weak` > `none` > `untestable`
（图形推理题干只有一句套话，文字层面无法检验——这类题只能靠原图，见 `audit_pairs.py` 拼图）。

当前 3926 题的判决（`python pipeline/verify_bank.py` 重跑即刷新）：

| 模块 | 题量 | 有答案 | 无问题 | 可疑 | 印刷锚点已证 | 需目检 | 逐题引用证据 | 选项不全 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 判断推理 | 989 | 988 | 920 | 69 | 988 | 0 | 3 | 5 |
| 数量关系 | 959 | 959 | 911 | 48 | 955 | 4 | 34 | 25 |
| 资料分析 | 1009 | 968 | 949 | 60 | 968 | 0 | 632 | 46 |
| 言语理解 | 969 | 965 | 942 | 27 | 963 | 2 | 2 | 7 |
| 合计 | 3926 | 3880 | 3722 | 204 | 3874 | 6 | 671 | 83 |

3880 道有答案的题里 **3874 道由印刷锚点定案**，剩 6 道仍需人眼；46 道没有答案的题
带 `no-answer` 标记，不猜。

**配对正确性有两级互相独立的证据**，任何一级成立都不依赖题号对齐逻辑：

1. **印刷锚点已证**：答案册被引用的那一页确实印着「N.【答案】X」，N 与本题印刷题号一致、
   X 与入库答案字母一致，且这一页同一高度上没有第二道题也用这个编号。图形推理这类
   "题干只有一句套话、文字无从检验"的题，就是靠这一级定案。
2. **逐题引用证据**（671）：解析开头的「根据题干“…”」引用与本题题干逐词对上。

「另一题的引用更贴合」这条判决要求**两个 token 以上的差距**：只差一个 token 是 OCR 噪声。
资料分析 624 道可检验的引用题中，414 道本题明显最优、207 道与别题完全并列（题干措辞相同的
题），0 道以两个 token 以上的差距指向别题；其余三个模块同样为 0。

**目检把机器定不了案的题目全部看过了一遍**（`python pipeline/verify_sheets.py --per 3`
渲染对照拼图：上=上册整题原图，下=下册答案原图，标签写明入库答案、印刷题号与未通过的那条
检验；四轮共目检 133 题）。找出来的问题不是"A 题配 B 的答案字母"，而是三类更细的缺陷：

- **考点介绍的编号段落被当成题目**（判断推理 2 题、数量关系 1 题）：`1.并列关系可以分为
  矛盾关系和反对关系。…` 这种讲解条目没有选项、没有真题标记，却和真正的第 1 题同号，
  于是把真题的答案抢了过去。`parse_bank.drop_prose_phantoms()` 按"无选项 + 无真题标记 +
  同号的真题紧随其后"把它剔掉，`pipeline/test_parse.py` 锁住这条规则。
- **答案字母对、解析文字张冠李戴**（`shared-answer-object` 2 题，另有 40 题字母已锚点证实
  但解析与题干词汇零重叠）：答案册里 `N.【答案】X` 与它下面的解析被切错了配对——字母跟着
  编号是对的，正文却是隔壁那道牛吃草题的。这类只可能靠目检发现，现已作为可疑项暴露在前端。
- **几何缺陷**：`answerPageRef` 方框落在相邻条目上、`pageRef` 页码与自身坐标矛盾（40 题）、
  答案册括号被读成 `（答案】`/`【答案）`/丢掉右括号（每册 6–12 条，早期正则只认 `【答案】`
  于是这些答案条目在配对视野里根本不存在）。前两类由 `python pipeline/snap_boxes.py` 统一
  吸附修正（重解析后必须再跑，已接进 `build.py`），括号问题改了三处正则
  （`bank_lines.py` 的上册行分类保持严格式：放宽会让普通行被当成答案条目、同一页区域被
  切成两道题）。

可疑项都带明确原因码（`no-answer` / `answer-not-in-options` / `anchor-letter-disagrees` /
`analysis-quotes-another-item` / `analysis-off-topic` / `empty-stem` / `stem-is-material-prose` …），
可在数据校验页按原因筛选后逐题打开核对。**没有被“猜”过去的答案**：证据不足或指向别题时，
宁缺毋滥，缺口以 `no-answer` 标记暴露在前端。

## 题型广场：多模块入口的设计

四个模块的题型、版式、复习节奏完全不同，所以入口不是"一个题库加个下拉筛选"，而是 `/`（题型广场）：

- **一模块一卡**：模块名 + 完成度环（已刷/题库）、题量与资料段数与图形题数三个 chip、章节分布前 6 项、
  已刷/正确率/待复习三格数据，四个动作（智能刷本模块 / 背题 / 错题本 / 题库），全部带 `?bank=` 参数下发。
- **未建完的模块显示真实识别进度**（`data/ocr/<tag>` 实际页数 / 该书总页数）而不是空壳或死链，
  并给出继续构建的确切命令；此时唯一动作是"浏览已识别页面"。
- **顶部全局条**：题库总量、已作答与覆盖率、累计正确率、待复习错题，以及"跨模块模考"入口
  （行测本来就是各模块合在一张文卷上，混合队列按各模块题量配比抽题）。
- **模块间不串台的三条规则**写在广场页脚：题号只在模块内有效（跨模块用 模块+章节+页码+原题号 定位，
  学习记录因此不会错配）；资料分析的同一组小题永远连续出现且共用上方吸附的资料面板；
  错题本/收藏/笔记/统计都可按模块切片。
- 原来的单页仪表盘保留在 `/overview`（趋势、薄弱考点、今日待复习），广场负责"选模块"，概览负责"看状态"。

## 功能设计

- **概览** `/`：两套题库的覆盖率、累计/今日正确率、待复习数、近 14 天趋势、最薄弱考点、章节进度、识别质量标记。
- **刷题** `/practice`：科目 → 章 → 节 → 考点逐级圈题；背题模式（直接看答案解析）、即时模式（逐题判分+解析+粉笔大数据正确率/易错项）、
  考试模式（答题卡 + 倒计时 + 交卷后回顾）、智能练习（未做 > 反复错 > 难题加权）、错题重做、收藏内练习；
  键盘 A–H 或 1–8 作答、Enter/→ 下一题、F 收藏、N 笔记；每题计时。
- **题库** `/bank`：科目切换 + 章→节→考点树导航 + 全文搜索 + 题型/作答状态/质量标记筛选 + 分页，链接可分享。
- **题目详情** `/question/[id]`：题干、图形、选项、答案、解析、来源、正确率、易错项、作答历史、笔记、原书对照。
- **错题本** `/wrong`：自动收录答错的题，Leitner 五关间隔重复（错→回到第 1 关并 1 天后复习；
  连续答对逐级升关，第 5 关自动"已消灭"）、到期筛选、按章节、错次排序、备注、批量重做/移出。
- **收藏 / 笔记** `/favorites` `/notes`。
- **统计分析** `/stats`：正确率趋势与 7 日均线、章节掌握度、考点雷达与考点明细表、
  日历热力图、选项偏好偏差（是否总蒙 C）、按真题难度分桶的正确率、历史测验列表。
- **原书** `/book`：按页浏览扫描图，题号框叠加并可点跳题目，用于核对 OCR。
- **数据** `/settings`：导出/导入整份学习记录 JSON、清空。

## 运行

```bash
pip install pymupdf rapidocr-onnxruntime opencv-python-headless   # 一次性
python pipeline/build.py                    # 所有科目的 OCR → 解析 → 裁剪（可中断重跑）
python pipeline/build.py --bank shuliang    # 只构建一个科目
python pipeline/ocr_queue.py                # 只想补 OCR 时（等外部进程停后再续跑）
python pipeline/snap_boxes.py                 # 把页框吸附到印刷锚点（重解析后必跑）
python pipeline/verify_bank.py                # 逐题校验：完整性 + 题↔答配对证据
python pipeline/verify_sheets.py --per 3      # 机器定不了的题渲染对照拼图，逐题目检
python pipeline/measure_quote.py ziliao       # 「根据题干“…”」证据的判别力标定
python pipeline/audit_pairs.py --bank shuliang   # 配对审计 + 抽样拼图
python pipeline/test_parse.py               # 解析规则回归测试
npm run dev                                 # http://localhost:3000
```

`npm run typecheck` 做类型检查。首次进入页面时 SQLite 会自动建表，无需迁移步骤。

## 已知局限（管线会持续收敛）

- 带圈数字（①②…）与分数上下结构识别不稳定，影响部分数量关系题的解析可读性——原书裁剪图可核对。
- 资料分析的排序题选项是 ①②③ 的排列，OCR 常读成 `4023` 这类数字串；这类题会打
  `options-circled` 标记并始终展示整题裁图，避免按错误选项作答。
- 资料分析每套作业题固定 1..20 重启编号，因此题号必须与「作业题序号」一起才唯一；
  题↔答用带空隙的序列比对（DP）配对，当前 1009 题中 968 题已配上答案，其余 41 题
  带 `no-answer` 标记而不是被猜一个答案；下册另有 52 个印刷锚点无人认领，逐条列在
